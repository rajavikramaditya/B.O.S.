## 2. Edge Routing & State Mapping

### Edge Mapping
Routing between nodes in LangGraph (conditional edges, fallback loops, direct jumps) maps directly to the B.O.S. Runtime Planner and Plan Executor:
- **Static Edges:** Maps to sequential steps inside the `ExecutionPlan` generated by the Planner.
- **Conditional Routing:** Maps to the B.O.S. `DecisionEngine` and dynamic replanning by the `Planner` if verification checks fail.

## 3. Checkpointing & Human-in-the-Loop

- **Checkpointing:** B.O.S. `PlanExecutor` checkpoints the state of the active `ExecutionPlan` at every step transition. If a task fails or a connection drops, the execution restarts from the last valid step UUID.
- **Human-in-the-Loop:** LangGraph interrupts correspond to the `Awaiting_Approval` state in the Plan Executor. The Policy Engine blocks execution and waits for a webhook event signaling a user confirm approval before resuming the plan steps.

---

## 4. Conditional Branching & Parallel Execution

- **Branching:** If-Else, loops, and fallback logic belong entirely to the B.O.S. Core Runtime (`DecisionEngine` and `Planner`). Business modules remain declarative and never execute routing commands directly.
- **Parallelism:** The B.O.S. Plan Executor supports async fan-out and fan-in of independent plan steps. Steps with no cross-dependencies are executed in parallel threads via the `CommandBus` execution pipeline.

---

## 5. Error Handling & Memory Model

- **Error Propagation:** Caught exceptions in adapters or providers are handled safely at the capability layer via `execute_safe()`. If a step crashes, B.O.S. runs the transactional rollback handlers of the affected plan execution.
- **Memory Separation:** B.O.S. maintains a cleaner separation of concerns than LangGraph:
  - **Conversation:** Volatile message trace.
  - **Execution:** Active plan state variables.
  - **Context:** Entity relationship graphs.
  - **Business:** Permanent record database.
